# 自定义 NPC：独立保存，不修改原生地图

原生 NPC 仍位于 `resource/map` 的地图文件中；本目录只保存自行生成的 NPC。
一只 NPC 一个 JSONC，按所在地图地区与地图名分目录。例如：

```text
resource/npc/custom/
  kanto/ViridianCity_Mart/npc_100000.jsonc
  kanto/ViridianCity_Mart/npc_100001.jsonc
  hoenn/LittlerootTown/npc_100000.jsonc
```

以上仅是路径说明。本次没有预置或实际生成任何 NPC；文件由游戏内命令自动保存。

## 生成

首次部署本次源码修改需要自行编译并重启游戏服。之后 GM 面对一格空地执行：

```text
//spawnnpc 68 0 0 0 0 0
```

六参数仍是外观编号、脚本偏移（只支持 0）、外观地区、移动类型、横/纵活动范围。
在角色前方生成并永久保存。命令反馈给出地图、固定序号、运行时编号和绝对文件路径。
保存失败不会把 NPC 发布到地图。客户端 NPC Tool 的 Spawn 按钮也使用相同流程。

事件模式也已接入，例如：

```text
//eventspawnnpc 0 248 10 0 0 0 0 -1 -1 false false false 1.0 0
```

支持无附加条件的手动生成，`0` 是万圣节分类，不自动开启节日活动。
事件条件、标志条件、覆盖已有 NPC 和忽略重复暂不支持，会明确拒绝。
参数说明见 [事件生成命令](../../../docs/CHAT_EVENTSPAWNNPC_COMMAND.md)。

## 文件示例

```jsonc
{
  "version": 1,
  "enabled": true,
  "map": "ViridianCity_Mart",
  "regionId": 0,
  "entityIdx": 100000,
  "spriteId": 68,
  "spriteRegion": 0,
  "movementType": 0,
  "leashX": 0,
  "leashY": 0,
  "x": 6,
  "y": 3,
  "z": 0,
  "toward": 2
}
```

示例字段说明，不表示该位置已通过你当前地图的实际占位校验。
`regionId` 是所在地图地区，`spriteRegion` 是外观来源地区，两者不是同一个字段。
`map` 为地图文件名去掉 `.json`；`x/y/z` 是出生位置；朝向 `0下、1上、2左、3右`。
所有字段必填。仅支持 `.jsonc`，UTF-8，允许注释；未知/重复字段、不完整内容和非法数值会拒绝。
每文件最多 16 KiB，全目录最多 10000 只，单地图启用实体总数（含原生）最多 1024。

普通生成仍写入上面的版本 1 格式。事件生成采用版本 2，在基础字段后增加三个必填字段：

```json
"eventId": 0,
"sparkles": false,
"spriteScale": 1.0
```

`eventId` 为编辑器事件分类，`-1` 表示普通 NPC，`0..6` 为节日分类，不是活动开关；
是否加载仍由 `enabled` 控制。缩放仅允许有限数值 `0.25..4.0`。
版本 1 不允许夹带扩展字段，读取时默认为无事件、无闪光、原尺寸；
已有文件无需转换。重启和删除停用都会保留版本 2 的视觉参数和分类。

## 编号与恢复

- 自定义 `entityIdx` 从 `100000` 起按地图分配。文件名必须是 `npc_<entityIdx>.jsonc`。
- 固定序号永久保存，不随重启或原地图增加 NPC 而改变。
- 如果未来原地图恰好也使用该序号，启动会报冲突，不覆盖原 NPC，也不自动改序号。
- 网络 Object ID 不写进配置，重新启动后由原有 ID 生成器分配；商店绑定使用固定序号。
- 启动顺序为原地图 NPC → 独立自定义 NPC → 商店目录，避免商店先查到不存在的自定义店员。
- 配置文件分开保存；运行时加入统一地图实体查询，便于客户端显示和交互。原地图 JSON 不会被写入。
- 自定义 NPC 沿用地图跨频道共享机制，当前游戏服进程的同地图所有频道都可见。

## 绑定商店

在对应店铺 JSONC 中填写命令反馈的地图和固定序号，再输入 `//reloadshops`：

```jsonc
"npcs": [
  { "map": "ViridianCity_Mart", "entityIdx": 100000 }
]
```

NPC 位置/外观文件只放本目录，商品和价格仍放 `resource/shop`，职责分开。

## 编辑、停用与安全

- 在线删除使用 `//eventdeletenpc <NPC运行时Object ID>`，仅处理当前主地图的已保存自定义 NPC。
  命令先保存 `enabled=false`，再立即移除所有可见客户端中的实体，并关闭该店员的商店报价。
  原生 NPC 不可删除；固定序号 `100000` 不是此命令的参数，重启后需获取新的 Object ID。
  详见 [删除命令说明](../../../docs/CHAT_EVENTDELETENPC_COMMAND.md)。
- 停服后编辑对应文件，再启动生效；`//reloadshops` 只重载商品/绑定，不重载 NPC 位置或外观。
- 停用时改 `"enabled": false`，保留文件和序号，避免将来误用该序号。商店中相应绑定也需移除。
- 不要在游戏服运行时移动、复制或改名配置文件，不要多个游戏服进程共用可写目录。
- 同目录临时文件写完并强制刷盘后，使用原子移动发布；不支持原子移动的文件系统会明确失败。
- `.write.lock` 是保存互斥锁文件，`.tmp` 是未发布的临时文件，两者都不是 NPC 配置。
- 新增保存不覆盖已有目标文件；删除仅在核对磁盘原定义后替换为停用配置，不物理删文件。
  拒绝不安全地图名、符号链接或越界路径。停用重写保留字段值但不保留手写注释或排版。
- 自定义目录任何坏文件、未知地图、重叠位置或编号冲突会阻止这一批自定义 NPC 加载并禁用新增，
  原生 NPC 不变。修正中文日志指出的文件后重启，不能忽略坏文件继续占用编号。
- 以前未保存的临时 NPC 不会自动转存，因为无法可靠区分它们与原生 NPC；部署新版后重新创建。

请备份本目录及 `resource/shop`。只备份原地图不会包含这些自定义 NPC。
完整命令与协议记录见 [命令文档](../../../docs/CHAT_SPAWNNPC_COMMAND.md)。
