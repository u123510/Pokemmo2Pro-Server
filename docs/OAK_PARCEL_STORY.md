# 大木包裹与图鉴剧情

## 实现边界

接在首次劲敌战斗之后：常磐市商店领取包裹、回研究所交付、获得图鉴与 5 个精灵球。
继续使用原生对话框和既有背包/图鉴同步，不新增客户端 UI 或未确认的事件旗标。
这是服务端重建的三个衔接场景，不是完整原版 ROM 脚本解释器；常磐老人捕获教学现已由
[独立章节](VIRIDIAN_CATCH_TUTORIAL.md) 接入，劲敌二战、尼比道馆及后续地区尚未实现。
妈妈治疗和开场流程继续保留。

## 配置和触发

配置文件：[resource/story/kanto/oak_parcel/chapter.jsonc](../resource/story/kanto/oak_parcel/chapter.jsonc)。

- `enabled`：只控制本章，不删除已有进度或物品，也不关闭普通商店。
- `text`：18 个现有客户端文本引用。数字是文本编号，不是剧情阶段、NPC 编号或任意脚本偏移。
- 精灵球固定为物品 `5004`，数量 `5`，匹配原生对白；包裹为物品 `349`，不要误用物品 `4`。
- 配置修改后重启游戏服读取；Java 变更需要自行编译。本章不支持 `//reloadshops` 热重载。

本章的任务 NPC 是固定剧情角色，不从商店商品 JSONC 猜测，也不使用每次启动变化的 Object ID：

| 地图资源名 | 地图元组（地区、组、地图） | 固定序号 | 职责 |
| --- | --- | --- | --- |
| `ViridianCity_Mart` | `(0,5,3)` | `npc_0` / `entityIdx=0` | 原店员，领取或补领包裹 |
| `PalletTown_ProfessorOaksLab` | `(0,4,3)` | `npc_3` / `entityIdx=3` | 大木，交付及授予图鉴 |
| `PalletTown_ProfessorOaksLab` | `(0,4,3)` | `npc_7`、`npc_8/9` | 劲敌、桌上图鉴的个人可见性 |

1. 完成首次劲敌战斗后进入常磐市商店，等客户端真实地图加载确认，自动播放店员对白。
   对话超时或中断时，也可以重新与原店员交互领取。
2. 店员请求对白确认后保存领取检查点，再显示原生“获得包裹”对白。
3. 返回研究所与大木交互，问候对白确认后扣除一件包裹并保存交付检查点。
4. 接续图鉴介绍；授予时把 5 个精灵球和完成检查点一起保存，再播放图鉴及精灵球获得对白。
5. 结束后恢复移动；博士提供返访对白，任务不再重复。完成领奖时隐藏当前玩家视野中的劲敌和桌上图鉴。

NPC 交互先检查是否有本章待办，再进入正常商店和其他 NPC 对话。
未完成开场、已经携带包裹、已交付或已完成玩家均可正常购物；其他店员不被本章拦截。
修改店铺 `npcs` 只改变谁卖商品，不会把“送大木包裹”的剧情一并转给新店员。

## 存档

复用 `character.oak_lab_status` 和 `oak_parcel_status`，不新增数据库表，也不自动清空旧记录。
`first_partner_status` 仍归开场负责，本章不改变初始选择或其他地区进度。

| `oak_lab_status` | `oak_parcel_status` | 本章阶段 | 断线/重登后 |
| ---: | --- | --- | --- |
| 0..3 | 0..3 | 开场未完成 | 不触发包裹，继续原开场检查点 |
| 4 | 0 或 3（历史默认） | 待领取 | 进入商店或与原店员交互领取 |
| 4 | 1 | 待交付 | 不再次发包裹；回研究所找大木 |
| 5 | 0..3 | 已交付，待图鉴 | 进入研究所自动接续图鉴介绍，也可找大木 |
| 4 | 2 | 兼容旧交付记录 | 同上，不再次扣包裹 |
| 6..9 | 0..3 | 本章已完成/旧后续阶段 | 不重播、不重复发 5 个球 |

领取时已有包裹则采用现有物品，只补存档标记。阶段 4/包裹状态 1 的玩家若主背包确实缺少包裹，
可以回原店员补领；已交付或已完成不能再补领。历史重复包裹不批量清除，交付只扣一件。
字段超出上述范围时明确报错并暂停本章，不自动当成新玩家或更改资产。

角色以 `id + account_id` 读取/锁定；物品以 `owner_id + inventory_id` 锁定并按物品编号排序。
领取、交付、五球奖励各自与对应检查点在同一事务提交。任何背包错误、编号冲突、存档比较失败
都会回滚该次操作。等待玩家看对白期间不持有数据库事务。

提交之后才更新 `CharacterData`、在线剧情状态、背包封包和 NPC 投影。当前服务端没有独立在线主背包缓存，
返回的背包快照来自事务内最终记录。非战斗登录/重连重读存档；读取失败时暂停，不回退旧缓存。
首次战斗在同一登录中结束后立刻可以接包裹，不必为了加载新阶段再重登。

对话回执的序号及一次性回调沿用原模块，过期或重复回执不能重复提交。
等待超过 120 秒会释放交互状态；网络断开只清理临时等待，不清空数据库检查点。
如果已经提交奖励但在最后几句对白之前断线，重登不再领奖，也不保证把最后一句对白再播一遍。

## 物品保护

物品 `349` 的现有 `Item.bin` 元数据不足以表达任务限制，因此在 `ItemManager.isStoryBound` 显式保护：

- `isTradeableForExchange` 拒绝包裹，现有玩家交易、邮件发送、GTL 上架/购买及商店规则复用此检查。
- `InventoryService` 拒绝丢弃；`PokemonItemService` 拒绝装备给宝可梦。
- `ItemUseService` 拒绝普通道具使用；只能由剧情事务交付。
- 新包裹写入关都地区标记 `0`；五球奖励使用普通无限制堆叠，不影响正常球道具使用或买卖。

主背包快照限制为 65000 字节以内、最多 65535 条，检查正数 Object ID/数量和 PvP 奖励时间字段。
可空旧元数据只在此次发送快照归一化为 `-1`，不顺手批量修改历史数据。

## 协议与客户端

没有新增 opcode、Packet 类型或客户端代码；使用已注册路径：

| 方向/opcode | 用途 |
| --- | --- |
| C2S `0x05` | 真正加载地图后启动/接续章节 |
| C2S `0x22`、`0x27` | 指定 NPC / A 键交互，限定当前地图和可见目标 |
| 双向 `0x21` | 原生对白与序号回执，格式不变 |
| S2C `0x40` | 每次提交后刷新主背包，包括包裹领取/消失和五球奖励 |
| S2C `0x0A` | 领奖时重新发送当前角色的真实图鉴记录 |
| S2C `0x12`、`0x08` | 按玩家独立显示/移除剧情 NPC |

对白依据客户端 `data/strings/strings_zh_dump.xml` 的已有引用，18 条编号保存在章节 JSONC，
静态检查会逐条确认存在。`0x21` 字段和回执依据见 [开场协议说明](PALLET_TOWN_STORY.md#协议依据)。

当前 MMO 客户端本就有图鉴界面。本章“获得图鉴”保存的是故事阶段，
`0x0A` 同步的是实际见过/捕获记录，并非未经确认的“图鉴菜单解锁包”。
尚未实现“领图鉴之前禁用图鉴按钮”、劲敌进门行走、精确镜头或逐帧原版演出；这些不能视为已验证。

## 修改入口清单

- `CharacterWorldLoader`、`CharacterEventService`、`RequestPlayerPacket`、`InteractPacket`、`GameProtocol` 改为转交 `StoryService`。
- `SceneInteractionService` 增加待办剧情在商店之前的分派；普通购物链不改协议。
- `ScriptManager` 加载章节；`GameServerService` 组装独立事务服务。
- `PalletStoryLifecycle`、`PalletStoryState`、`PalletStoryNpcs` 支持两章共同的登录清理、包裹状态和个人投影。
- `PalletOpeningService` 的共享失败日志使用通用“剧情执行失败”，不把新章异常误标为开场异常。
- 物品保护入口见上节；新文件完整链接见 [源码索引](SOURCE_FILE_INDEX.md)。

## 测试存档重置

本章没有新增重置命令，也不会自动修改你的测试角色。先完整退出并备份，再由维护者修改对应角色：

- 只重玩包裹章：`oak_lab_status=4`，`oak_parcel_status=3`，保留初始选择和队伍。
- 包括开场全部重玩：`oak_lab_status=0`、`first_partner_status[1]=3`、`oak_parcel_status=3`。
  SQL 数组下标从 1 开始；具体开场触发位置见 [开场重置说明](PALLET_TOWN_STORY.md#重置后未触发)。
- 修改不会自动回收已领宝可梦、精灵球或图鉴记录，再走一次会再次发奖励；只对测试角色使用。
- 不要在进行中的战斗或在线角色上改表。完整重登会读取新检查点，单改数据库不会实时更新当前客户端。
