# 合众死亡存盘点

2026-10-27 `update`：将用户提供的 14 条合众 POINT 定义接入资源加载，编号由 21..34 调整为 200..213。
`UNOVA_HOME` 为 200，13 个中心点按原顺序为 201..213。

## 配置与职责

配置位于 `resource/death_save/unova.points`，由 `ScriptManager` 从 map 目录的同级目录加载。
格式为 `POINT id key sourceMap destinationMap x y z option1 option2`；地图键、坐标和末尾两值原样保留。
末尾的 `1 0` 语义尚未验证，以原始选项保存，不将其解释为客户端协议字段。
回城保留角色当前朝向，交通状态重置为既有的步行值 0。

`org.pokemmo.gameserver.game.character` 中的 `DeathSavePoint`、`DeathSavePointCatalog` 和
`DeathSaveRuntime` 分别负责不可变点定义、严格配置校验和角色回城流程；依赖现有地图、角色、
宝可梦与服务接口，不执行 SQL。`org.pokemmo.gameserver.services.character.DeathSaveStore`
集中保存角色的合众存盘点，并在同一事务中恢复 PARTY 和保存回城坐标；不发送封包或改变在线对象。

目录拒绝重复编号、重复 key、重复触发地图、非合众地图键、缺失 HOME、非法坐标、错误列数和非整数。
编号只允许 200..213；读取旧存档编号 21..34 时按顺序映射为 200..213，新写入只使用新编号。

## 运行流程

完成 C2S `0x05` 地图加载确认、角色不在战斗且位于合众时，按当前地图 key 查找 sourceMap，
将对应编号保存到 `death_save.unova_point_id`。HOME 的触发地图为 `Unova_Map_391`，回城地图为
`Unova_Map_390`；中心点使用各自同一张地图。没有存档记录时默认 HOME 200。

合众野生战斗或普通训练家/劲敌/道馆/天王战斗的 DEFEAT 经 C2S `0x33 BattleFinishSuccessPacket` 进入回城流程。
`0x33` 为无 payload 的战斗结束确认；`0x05` 为无 payload 的地图加载确认；opcode 与字段布局沿用既有注册。
玩家单挑、观战与其他地区不使用这组点。请求必须来自角色当前有效会话，旧连接回执不触发存盘或回城。
必须先找到已加载、地区为 2 的目标地图并验证落点可行走，再按角色 ID 和账号 ID 锁定角色，
检查存盘点没有变化，在同一事务中恢复队伍 HP/PP/异常状态并保存位置。
提交成功后才更新在线对象、发送既有宝可梦增量包并加载目标地图。不新增 opcode。

找不到目标地图、落点无效、存档编号无效、归属/队伍不一致或数据库失败时，记录原因并向玩家发送失败通知，
不保存无效位置，不发送回城成功；保留战斗上下文以便修复配置后重连重试。
回城后地图确认不再触发一次新的战败恢复。

## 数据库与部署前提

新库定义在 `db/schemas/init.sql`；已有库需由维护者执行
`db/schemas/migrate_unova_death_save.sql`。代码不会在启动时修改 schema。
迁移增加 `unova_point_id`，默认 200，并把历史 21..34 转成 200..213；jOOQ 生成文件不手改，
新增列暂由存储服务使用带类型的 jOOQ DSL 访问，后续重新生成模型即可。

当前仓库尚未包含合众地图资源。合众标准化的带 `terrain` NDS 地图 JSON 的加载入口已接通，
其内部矩阵/地形/行为契约与现有 `SinnohMapConfig` 相同，不直接解析原始 Black/White ROM 数据。
实际启用回城前必须提供对应 sourceMap/destinationMap 的真实地图定义，名称与配置完全一致，
并使用实际地形确认落点。合作战斗和副本 Boss 不走本次普通回城流程。
因此，本次完成配置、持久化和回城调用链；缺失地图时会明确失败，不能据此宣称客户端死亡回城已经验证。
