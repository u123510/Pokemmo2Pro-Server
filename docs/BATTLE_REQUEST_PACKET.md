# 玩家单挑请求封包

## C2S `0x25`

客户端 `f.Bs0` 使用 C2S `0x25` 向当前地图玩家发起单挑。字段顺序为：

| 顺序 | 字段 | 编码 | 说明 |
| ---: | --- | --- | --- |
| 1 | 目标名称 | UTF-16LE、NUL 终止 | 最多 32 个字符 |
| 2 | 战斗格式 | byte | `0` 为单打；当前服务端只接受单打 |
| 3 | 辅助字段 | byte | 客户端协议保留字段 |
| 4 | flags | byte | 按位决定后续可选字段 |
| 5 | `flags & 0x08` | byte | 保留战斗设置 |
| 6 | `flags & 0x10` | byte | `N2` 设置，当前校验范围 `0..6` |
| 7 | `flags & 0x20` | byte + entries | GV 数量及条目；启用型条目追加一个参数字节 |
| 8 | `flags & 0x40` | byte | 尾部保留参数 |

示例抓包：

```text
25 4C 00 4D 00 00 00 00 00 50 00 05
```

该包表示目标 `LM`、单打格式 `0`、flags `0x50`，包含 `N2 = 0` 和尾部参数 `5`。
服务端会完整消费可选字段并拒绝未知 flags、非法长度、截断数据和未消费尾部。

请求目标必须在线、同频道、同地图且双方都有存活 PARTY 宝可梦；战斗、交易、其他交互或已有请求
都会拒绝。通过后服务端向目标发送 S2C `0x21` 的 `REQUEST_BATTLE` 确认框，目标用 C2S `0x21`
的 `type = 0/1` 拒绝或接受。接受后创建共享 `PlayerBattle`，分别向双方发送已有 S2C `0x30`
战斗初始化包。请求 30 秒超时、断线、拒绝或状态失效时清理，不写入数据库。

## S2C `0x21`

单挑确认框复用通用交互包，客户端线上交互类型为 `20 (0x14)`，交互头后追加发起者名称。当前
客户端会继续按单挑请求解析器读取以下字段；缺少尾部字段会导致客户端读取越界并丢弃整个交互包，
因此不会创建接受、拒绝和拉黑按钮。

| 顺序 | 字段 | 编码 | 当前服务端值 |
| ---: | --- | --- | --- |
| 1 | 交互次数 | byte | 目标当前交互次数 |
| 2 | 交互类型 | byte | `20 (0x14)`，客户端 `REQUEST_BATTLE` |
| 3 | 字符串偏移 | int LE | `0` |
| 4 | 实体 ID | long LE | `-1`，不是地图实体交互 |
| 5 | 交互延迟 | int LE | `0` |
| 6 | 本地化参数数量 | byte | `0` |
| 7 | 发起者名称 | UTF-16LE、NUL 终止 | 请求者角色名称 |
| 8 | `Cq` 战斗类型 | byte | `0`，默认单打/普通战斗类型 |
| 9 | `Jh0` 规则设置 | byte | `0` |
| 10 | `my0` 设置值 | byte | `0` |
| 11 | 请求 flags | byte | `0`，不启用可选字段 |
| 12 | `yW` 辅助值 | byte | `0` |
| 13 | `Qo0` 辅助值 | byte | `0` |

好友和交易请求使用客户端的其它交互解析分支，仍只在名称后读取各自定义字段；本次补齐的 6 字节尾部
仅适用于线上值 `20 (0x14)` 的 `REQUEST_BATTLE`。当前 `Cq`、`Jh0`、`my0`、`yW`、`Qo0` 的非零展示
语义，以及 flags 的可选规则数组仍未完全验证；本实现只发送已验证可被客户端完整消费的默认值。
