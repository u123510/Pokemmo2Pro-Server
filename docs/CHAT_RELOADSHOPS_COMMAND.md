# `//reloadshops` 店铺配置重载

命令实现位于 `org.pokemmo.gameserver.command.commands.ReloadShopsCommand`，
通过 `GameCommandModule` 注册，沿用 `Command` 默认 GM 权限。

```text
//reloadshops
```

不接收参数，额外参数返回中文用法，不执行重载。命令只扫描 `resource/shop` 下的
`.json` / `.jsonc`，不执行编译、地图重载、数据库迁移或全局物品价格修改。

每个文件是一家店铺，字段为 `shopId`、`buyEnabled`、`sellEnabled`、`items`，
以及可选的 `npcs: [{"map": "ViridianCity_Mart", "entityIdx": 0}]`。
必须先成功校验全部候选文件，再原子替换当前版本。失败会在日志指出文件和字段，
聊天反馈失败原因，旧配置与旧报价保持不变。成功会报告店铺数量、版本，并关闭旧版本窗口。

进行中的交易持有目录读锁直到事务和在线同步完成；重载发布新版本时使用写锁。
因此一次交易不会在中途切换价格。重载后的旧报价即便还有延迟请求也会被版本校验拒绝。
多个重载请求串行执行，不会让较早读到的文件覆盖后来已经发布的结果。

商品、价格和店铺 JSONC 中的 NPC 绑定修改，使用此命令即可一起生效。绑定检查使用
已加载的地图与 NPC；名称不唯一、未加载、序号不存在或被多店重复指定都会拒绝重载，
不改变当前在线绑定或价格。`npcs` 存在时完全覆盖本店旧地图绑定，`npcs: []` 明确解绑；
省略 `npcs` 才兼容地图 `shopId`。新增、更换或取消店员不需要再修改地图或客户端。

若实际修改的是地图文件中的 NPC 坐标、外观、旧式 `shopId`、柜台，或新增地图/NPC，
仍需要重新加载地图资源或重启游戏服。这个命令不生成 NPC，也不改变原脚本和隐藏条件。

初次启动没有旧快照时，坏文件、重复 `shopId` 及 NPC 绑定冲突的店铺不会启用，其余合法文件可用；
运行时重载采用整批校验、整批切换，避免部分价格变化。空目录代表关闭全部配置店铺。

本次只进行了静态检查，未启动服务器执行该命令。协议与客户端配套说明见
[商店协议](NPC_SHOP_PACKET.md)及[客户端方案](NPC_SHOP_CLIENT_INTEGRATION.md)。
