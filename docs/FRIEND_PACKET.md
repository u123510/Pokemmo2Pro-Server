# 好友操作封包

## C2S `0x60`

客户端添加或移除好友时发送 C2S `0x60`。客户端 `f.T20` 的构造值为十进制 `96`，在线上即
wire opcode `0x60`；字段按 UTF-16LE 写入并以两个零字节结束。

抓包示例：

```text
60 4B 00 79 00 75 00 00 00 2D 00 2D 00 00 00
```

| 偏移（含 opcode） | 字段 | 编码 | 示例 |
| ---: | --- | --- | --- |
| `0x01` | 目标玩家名称 | UTF-16LE、NUL 终止 | `Kyu` |
| `0x09` | 附加字段 | UTF-16LE、NUL 终止 | `--` |

客户端根据本地好友表决定菜单显示“添加好友”或“移除好友”，但两种操作都复用 `T20`，服务端
不能仅从该封包区分动作。第二字段在当前客户端调用中固定为 `--`，具体业务含义尚未验证。

服务端现在由 `FriendActionPacket` 注册并消费该请求，校验两个字段的 UTF-16LE 终止符、最大长度、
尾部数据和非空目标名称，因此不会再因未注册 opcode `96` 关闭 Session。目标已有关系时，服务端立即
删除 `player_id -> friend_id` 并回发 `0x63`；目标没有关系时，服务端要求目标在线并通过 S2C `0x21`
发送 `REQUEST_FRIEND` 好友请求 UI，此时不写数据库。目标通过 C2S `0x21` 返回 `0` 拒绝或 `1` 接受；
接受后 `FriendService` 在事务中同时写入双方关系，并分别向 A、B 发送 `0x63` 完整列表。请求 30 秒
超时、断线或目标正忙时会清理待处理状态。客户端无法从 C2S `0x60` 区分添加和移除，因此仍由客户端
本地 `0x63` 列表决定菜单文字；旧的 `toggleFriend` API 仅为兼容保留，好友封包不再直接调用它。

## S2C `0x21` 好友请求 UI

好友请求复用通用交互封包，但使用独立的交互类型 `REQUEST_FRIEND`。服务端内部枚举值是 `17`，
当前客户端在线上使用的交互值是 `21 (0x15)`；该值不会进入交易状态。
服务端发送的字段顺序如下：

| 顺序 | 字段 | 编码 | 说明 |
| ---: | --- | --- | --- |
| 1 | 交互次数 | byte | 目标当前交互次数 |
| 2 | 交互类型 | byte | `21 (0x15)`，即客户端线上的 `REQUEST_FRIEND` |
| 3 | 字符串偏移 | int LE | 当前为 `0` |
| 4 | 实体 ID | long LE | 当前为 `-1`，请求不是地图实体交互 |
| 5 | 交互延迟 | int LE | 当前为 `0` |
| 6 | 本地化参数数量 | byte | 当前为 `0` |
| 7 | 发起者名称 | UTF-16LE、NUL 终止 | A 的角色名称 |

B 的客户端随后发送 C2S `0x21` 的两个 byte：`type = 0` 表示拒绝，`type = 1` 表示接受。接受时服务端
才写入双方 `friend_list` 记录并分别刷新双方的 `0x63`；请求会在 30 秒、断线或目标进入其他交互时失效。

## S2C `0x63`

世界加载、好友关系接受或删除后，服务端都会发送完整列表并使用模式 `0` 替换客户端本地好友表；
单纯发起好友请求不会刷新 A 的列表，因此 A 在 B 接受前仍显示“添加好友”。
条目数是一个无符号字节，单包最多发送 255 条；列表按 `add_time`、`friend_id` 升序排列。

| 顺序 | 字段 | 编码 | 说明 |
| ---: | --- | --- | --- |
| 1 | 模式 | byte | 当前固定为 `0`，表示清空并重建列表 |
| 2 | 条目数 | byte | 最多 `255` |
| 每条 | 好友 ID | long LE | `friend_list.friend_id` |
| 每条 | 添加时间 | int LE | `add_time` 转 UTC Unix 秒 |
| 每条 | 在线 | byte | 通过 `GameSessionPool` 判断，在线为 `1` |
| 每条 | 好友元数据 | UTF-16LE 名称、byte、int LE、byte、short LE x4 | 名称使用角色当前名称；其余客户端尚未确认的字段暂写 `0` |

数据库初始化使用 [`db/schemas/init.sql`](../db/schemas/init.sql) 中的复合主键
`(player_id, friend_id)`、两个角色外键和禁止自加好友约束。已经使用旧表结构的数据库可先执行
[`db/migrate_friend_list.sql`](../db/migrate_friend_list.sql)，再重新生成 jOOQ 代码；现有生成代码
禁止直接手工修改。
